五个输出不会混成一个

Q 的形状是 [B,H,Tq,d]，其中 Tq=5 这个轴一直保留。每个 query 沿自己的候选位置轴做 softmax、加权求和，最后得到 Y [1,5,4]，仍然是一 token 对应一行输出。

本例只画注意力子层。如果接着要生成第 6 个 token，通常会用最后一个输入位置的最终表示经过词表输出层来预测；这与本层仍然计算 5 行表示是两件事。

为什么能并行，又看不到未来？

在同一层中，5 行输入都已经由上一层给出，可以一起做线性投影。第 t 行的注意力不依赖“本层第 t−1 行先算完的输出”，它读取的是本层由输入投影得到的 K、V。

并行处理的是已知输入；约束来自 mask：s>t 的分数设为 −∞。它不等于把待生成的 5 个未知 token 一次性生成出来。

只有一个候选时怎么凑 Top-2？

第 0 行只有位置 0 合法，所以有效数量 k_eff(t)=min(k,t+1)。图中为了画成规则张量，补一个空槽“—”，并给它 valid=false、logit=−∞、softmax 权重=0。

这是教学用的矩形表示，实际 kernel 可采用其他布局。空槽不是新的 token，也不能作为真实数组下标读取未来缓存。

如果前面已经有 P 个 token 呢？

新输入仍是 [1,5,4]，但总缓存长度变成 L=P+5，Indexer 矩阵变成 [1,5,P+5]。新块第 i 行能读所有 P 行旧缓存，再加新块的 0～i 行。

主 MLA 可以直接在压缩 C 上计算，避免显式展开 Kᶜ、V；本图保留展开步骤，方便与你发来的 MLA 图对应。缓存不会因为本轮未选中而被删除。

这是简化教学例子：沿用上一页的前 5 行输入与投影权重，Indexer 省略 LayerNorm、RoPE、Hadamard、FP8 量化及缩放细节。k=2 用来展示逐行选择；官方 V3.2-Exp 配置 k=2048，在只有 5 个可见 token 时会保留全部因果有效位置。本图展示逻辑稀疏读取，未承诺参考实现一定物化这些紧凑张量。
