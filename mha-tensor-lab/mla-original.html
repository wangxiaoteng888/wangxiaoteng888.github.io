原始 MLA：压缩每个 token 的 KV，保留全部因果历史。

从底部 input 向上读。这里回到 V2 / V3 系列 MLA 的经典结构，采用显式展开 K/V 的画法。绿色标出实际保存的压缩缓存；橙色是 RoPE；紫色是主注意力。沿用你最初的 16 头教学尺寸，方便和旧图逐节点对照。

本图的压缩是特征维度压缩：每个 token 保存 512 维内容 latent + 64 维位置 Key。128 个 token 仍有 128 份缓存，不会像 CSA 那样变成 32 个条目。图中没有 Indexer、Top-k、SWA 窗口或 V4 attention sink。

① 两条低秩路径，处理什么？

Query：7168 → 1536 → 16×192。先降维得到 qr，再上投影生成各头 Q。KV：联合投影输出 576，拆成 512 维内容表示和 64 维位置 Key；512 维再上投影生成各头 K_nope 与 V。

这些权重是模型本身的可训练参数。“低秩”描述中间表示与因子化结构，不等于微调时额外加上的 LoRA adapter。原始架构的 Q 压缩与 KV 压缩也不承担同一种缓存作用。

② 两个 compressed_kv 名字，重新区分

下方改名为 kv_a_proj / 联合输出：576 维，尚未处理。上方的 compressed_kv 指拆出的 512 维部分，经过 RMSNorm 后写入 C_cache。64 维 k_pe 从同一个 576 维输出拆出，经过 RoPE 后写入 Kᵣ_cache。

因此可以把最终缓存逻辑拼成 576 维，但它不是把联合投影刚算出来的那 576 维原样存下。两份缓存也可以分开存；绿色节点不是重复两套缓存。

③ 注意力：对应头相乘，再加权 V

score[h,t,s] = (q_nope[h,t]·k_nope[h,s] + q_rope[h,t]·k_rope[s]) / √192

不同主头各自计算；Q 的 head 1 不与 K 的 head 2 做这次点积。对 s 轴应用因果 mask，再做 softmax。每行权重对该头的 V 加权，最后拼头、输出投影。

NoPE 表示不做 RoPE，仍然需要投影。K_rope 由所有主头共享；广播后的 16 头表示不需要在缓存中存 16 份。

④ 缓存到底有多大？

这里计算的是逻辑元素数，不含 dtype、量化 scale、padding、分页和运行时元数据。Q 不进入跨 token 的 KV Cache；原始 MLA 会保留历史各 token 的内容 latent 与位置 Key。

⑤ 为什么图上展开 K/V，缓存却只存 latent？

展开图方便理解：K_nope=C·Wᵁᴷ，V=C·Wᵁⱽ。但高效解码可以重排线性计算，避免为历史 token 物化全部头的 K/V。

内容分数：(Q_nope·Wᵁᴷᵀ)·Cᵀ
头输出：(A·C)·Wᵁⱽ

每头将 Q 从 128 维映射到 latent 的 512 维，与 C_cache 点积；位置分数仍使用 RoPE 分支，缩放仍为 √192。A·C 得到 512 维后映射到 128 维 Value 输出。吸收的是每头上投影权重，不把 RMSNorm 或 RoPE 合并成固定线性矩阵。

⑥ 和刚才几张图怎么对应？

本图 MLA：压缩每个 token 的 KV 表示，主注意力看全部因果可见位置。旧 DSA 图：在 MLA 上用 Indexer 选择位置。旧 SWA 图：展示用窗口规则选位置的教学组合。

V4 CSA 图：还加入序列压缩，并组合压缩 Top-k 与局部窗口；采用共享 K=V 与新的输出结构。因此它不是原始 MLA 这张图简单地再多画一个框。
