把扫描框打开：5 个 token 怎样依次改写 S？

下面只放大一条请求、一个内部通道，该通道有 N=3 个状态分量。u 已经过卷积和 SiLU；Δ、Bₜ、Cₜ 已由当前输入算出。使用人工数值演示扫描核心，不代表训练模型，也没有数值模拟前后的投影、卷积和门控。

S₀ → token 1 → S₁ → token 2 → S₂ → … → token 5 → S₅

每个 Sₜ 都是同样大小的 3 维向量；解码时改写同一份状态。下方把历史步骤摆在一起是为了讲解，并不表示要缓存 S₁…S₅。

① 从 4 维到 16 维，为什么又拆成 8 + 8？

小例子中模型维 D=4，内部宽度 E=2D=8。输入投影输出 2E=16，拆成内容 x 和门控 z，各 8 维。x 进入卷积与状态空间模型；z 经 SiLU 后逐元素控制输出。

这里的 E 是内部通道数，不是 attention 头数。Mamba-1 这张图没有 MLA 那种 head 轴。

② Bₜ、Cₜ、Δₜ 在选择什么？

Bₜ 控制当前输入如何写入各状态分量；Cₜ 控制从哪些状态分量读出；Δₜ 影响旧状态的保留率与当前输入写入量。它们随输入变化，所以叫 selective。

这是连续数值的调节，不是 DSA 的 token 索引选择。Bₜ、Cₜ 可以有负值，SiLU(z) 也不是 0～1 的概率。

③ 实际缓存哪一部分？

conv_state 保存卷积前 x 的最近 K 个值（官方实现的缓冲布局）；ssm_state 保存最后一步 S。每层、每条请求各有自己的状态，请求之间互不计算。

长期历史通过更新后的状态影响结果，不意味着可以无损恢复每个历史 token。缓存的形状不随历史长度增长，但状态的数值持续变化。

④ 一次输入 5 个，必须一个接一个慢慢算吗？

数学关系是因果递推。整段输入时，卷积和参数投影可以批量进行，递推可用并行 scan 求解，不要求在 Python 中逐 token 循环。解码则读取旧状态，处理一个新 token，再写回。

固定模型尺寸下，扫描核心工作量随长度 T 线性增长，没有显式 T×T attention 张量。这不代表整个模块只有扫描的开销；投影、卷积及训练中间激活也需要计算和内存。

⑤ 不做 RoPE，怎么知道顺序？

这个原始 Mamba-1 mixer 没有 RoPE。因果卷积和 Sₜ 依赖 Sₜ₋₁ 的更新顺序已经引入了序列顺序。交换两个 token，后续状态一般就会改变。

小例子从零状态开始；Decode 接着已有状态继续处理，而不是每个新 token 都重置。

⑥ 这张图在完整模型的什么位置？

图中 input 是送入 mixer 的 hidden states。常见外层结构是 H → Norm → Mamba mixer → 与 H 残差相加；堆叠多层后再经过最终归一化和词表输出头。

为了和前面的 MLA 模块图对齐，这里没有把 embedding、外层 Norm / residual、LM head 混进内部状态图。图中的 D_skip·u 是 SSM 内部直连，不能代替外层 residual。

记号：b=batch，T=本次 token 数，D=model dim，E=内部通道，N=每通道状态维，R=dt_rank，K=卷积核长度。Bₜ 是输入相关写入参数，与 batch 的 b 不同。小例子 N=3 用于教学；大尺寸也仅为结构示例，不对应特定发布权重。图采用易读的 [b,T,feature] 逻辑布局；官方扫描内核常用 [b,feature,T]。绿色缓存按实现布局标注。

递推按官方实数 Mamba-1 实现：A = −exp(A_log)，ā = exp(ΔA)，写入项 = ΔBₜuₜ。不将写入项冒充为一般连续系统的精确 ZOH 公式。参数图显示逻辑依赖；融合内核无需把所有逐步中间张量完整物化。
