先看第一张：你原来的主链保持不变

Q 和 K 算出主分数后，新增一个加法：attn_scores + index_mask。mask 在选中列填 0，其余填 −∞；softmax 后，未选位置权重为 0。主注意力矩阵形状仍是 (2,16,128,128)。

原图将点积和 softmax 合在了 attn_weights 之前。这里仅把这两步展开，方便看到 Top-k 的接入位置。完整矩阵加 mask 是直观的等价写法，也对应官方参考代码的一种实现；它没有省掉已经计算过的完整 QK。

再切第二张：省计算时怎么做

Top-k 编号先选出每个 query 的 K/V；主 QK 和 AV 只处理这些候选。若 k=32，主分数形状变为 (2,16,128,32)。每个 query 选的位置不同，所以选中的 K/V 多出一个 query 轴。

这张图用展开 K/V 的路径与你原图对照；实际可以按索引直接读取压缩缓存，结合 MLA 的吸收计算，避免物化巨大 selected 张量。图中的 gather 表示逻辑选行。

维度如何选的？

沿用你的主链：B=2、T=128、D=7168、主头 H=16、q_lora_rank=1536、KV latent=512、每头 NoPE=128、RoPE=64、Value=128。Indexer 示例使用额外的 Hᴵ=64 个头、每头 dᴵ=128；它们与主 MLA 头不是同一组。

默认 k=32 是教学设定。官方 V3.2-Exp 配置 k=2048；如果只有 128 个 token，就会保留全部因果有效位置。选择 2048 可看到这种情况。此页不是一份完整真实模型配置或张量并行切分声明。

新增分支没有改变主 KV Cache

主缓存仍是归一化后的 compressed_kv（512 维） 与做过 RoPE 的 k_pe（64 维）。Indexer 另有自己的 index_k 缓存；量化实现还存相应 scale。

同一 query 的 16 个主头共享一组 Top-k 编号；不同 query 各自选择。每行只能选 s≤t 的位置，不足 k 个时需要无效槽 mask，不能读取未来 token。
