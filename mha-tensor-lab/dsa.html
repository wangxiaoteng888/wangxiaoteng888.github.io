03 / DEEPSEEK SPARSE ATTENTION

先选哪几个 token，
再让 MLA 认真计算。

在你熟悉的 MLA 前面，加一个 Lightning Indexer。它为当前位置挑选 Top‑k 个候选；主注意力只在这些位置上打分、归一化和汇总。

Indexer → Top‑k token IDs
→ 读取选中的 [Cᴷⱽ | Kᴿ]
→ MLA 打分 → softmax → 加权输出索引分数 ≠ 注意力权重
本轮不读取 ≠ 从 KV Cache 删除
B=1 · T=66 个教学 token；位置编号从 0 开始
D=4 · H=2MLA 输入四维；主注意力两个头
Hᴵ=2 · dᴵ=2Indexer 两个打分头；每头两维
d꜀=2 · dᵣ=2MLA 主缓存每 token 共 4 个数
k=2 → 可调每个 query 共享一组 Top‑k token IDs

范围：DeepSeek-V3.2 / V3.2-Exp 的 DSA 设计。数值是自制简化示例，绝非训练权重；这里用 k=2 展示筛选，官方模型的 k 配置为 2048。主 MLA 保留教学版 RoPE；Indexer 为了便于手算，仅演示线性投影与打分公式，省略其 LayerNorm、RoPE、Hadamard 变换、FP8 量化与缩放细节。

对照代码：一次 query 的稀疏 MLA

伪代码采用行向量，省略 batch、量化和分页。这里只在选中位置计算主注意力。网页另算一份 dense MLA 作为教学对照，它不参与 Top‑k 选择。

# t 是当前 query 的原始位置，包含当前位置的缓存已写入。
L = t + 1
qI = CQ[t] @ W_QI                 # reshape -> [HI,dI]
kI = X[:L] @ W_KI                # [L,dI]，每个 token 一份
wI = X[t] @ W_WI                 # [HI]，不是 softmax 概率

per_head = relu(qI @ kI.T)       # [HI,L]
index_score = sum(wI[:,None] * per_head, axis=0)
ids = topk(index_score, min(k,L)) # [k_eff]，原始 token 位置

Csel = C_cache[ids]              # [k_eff,dc]
Rsel = KR_cache[ids]             # [k_eff,dr]，已做原位置 RoPE

for h in range(H):               # 所有头使用同一个 ids
    # Qhat 是已吸收 Key 上投影的内容 Query
    logits = (Qhat[t,h] @ Csel.T
              + QR[t,h] @ Rsel.T) / sqrt(dk + dr)
    A[h] = softmax(logits, axis=-1)   # [k_eff]
    latent[h] = A[h] @ Csel          # [dc]
    Z[h] = latent[h] @ UV[h]         # [dv]
Y = concat(Z) @ WO                  # [D]

# 追加缓存时保存：
# 主缓存：C_new + KR_new
# 索引缓存：KI_new（实际量化时还有 scale）
# 绝不因为这个 query 没选中某行，就删除该行。
Indexer 怎么学会选？

它不是一条手写的“最近几个 token”规则。V3.2 的训练先保留稠密主注意力，用主注意力的聚合分布监督 Indexer；随后引入稀疏选择，让主模型适应选出的集合，并继续训练 Indexer。

因此不能把一个未训练的 Indexer 随意接到已有 MLA 上，就期待保持原模型质量。本页权重仅用于计算示范，不用于解释中文词语之间的真实重要性。

理论稀疏，为什么参考代码还可能算整张分数？

“先算完整分数，再把未选中位置设成 −∞”能表达相同数学结果，但不会自动省掉前面的完整矩阵乘法。高效实现需要让稀疏 kernel 按选中的索引读取和计算；短序列也可能采用稠密计算加遮罩的实现策略。

页面中的 gather 是逻辑上的取行，实际 kernel 可以直接按页表与 token IDs 访问，并不一定真的复制出一个独立小矩阵。

KEEP THIS MAP / DSA 速查

缩短的是本轮注意力的 key 长度。

Indexer heads ≠ MLA heads

前者把各自的 ReLU 点积加权汇总成一组排名；后者在同一组选中位置上，独立计算真正的注意力分布。两种头的数量可以不同，本例恰好都设为 2。

Top‑k IDs ≠ KV Cache

IDs 是当前 query 的访问清单；Cache 是历史表示的存储。切换 query 后清单会变化，同一行缓存可能这次不选、下次又被选中。

稀疏不等于“完全无损”

仅保留部分 token 通常改变 softmax 分母和最终输出。DSA 依靠训练保持任务表现；不是对 dense attention 做恒等变换。k 覆盖全部可见位置时，本页两者才一致。

假设某次 query 没有选中 token 1，接下来应该怎样处理它的缓存？

教学实例 所有数值人工构造；token 划分不代表实际分词。主 MLA 使用与上一课相同的权重形式，位置角度为 θ=t·π/4。显示值保留三位小数，计算使用未舍入值。Indexer 同分时本页按原位置升序取，实际 kernel 的同分选择规则可能不同。
