和你发来的那张 MLA 图怎么对应？

你图里的 q_nope、q_pe、k_nope、k_pe、value_states 都还在。这里用 Qᶜ、Qᴿ、Kᶜ、Kᴿ、V 表示它们。原来对全部 L 个位置计算，现在通过 Top-k，只对 k 个位置计算。

例如沿用你图的 B=2、H=16、Tq=128，若可读前缀 L=4096、教学设定 k=32，则注意力分数从 [2,16,128,4096] 变为 [2,16,128,32]。每个 query 各自选 32 个位置，同一个 query 的 16 个主注意力头共享这些编号。

官方 V3.2-Exp 的 k 配置为 2048。如果总共只有 128 个可见 token，就没有“从 128 个里只选 2048 个”的稀疏收益：可见位置都会保留。

为什么图里展开了 K、V？

这是为了和你原图逐项对上：先把选中的压缩向量 C 解成 Kᶜ、V，再计算。实际 MLA 可以把矩阵乘法合并，避免显式展开这些张量。

对每个头，等价计算是 Q̂=Qᶜ(Uᴷ)ᵀ，然后用 Q̂Cᵀ + Qᴿ(Kᴿ)ᵀ 打分；加权得到 A C，再做 (A C)Uⱽ。两种写法都只读 Top-k 选中的 C、Kᴿ，DSA 的位置选择不变。

本图的 Gather 表示逻辑选行；稀疏 kernel 可以直接按编号读取缓存，并不一定创建一份独立的 selected 张量。

缓存没有被删掉

主 MLA 仍缓存所有有效历史 token 的 Cᴷⱽ 和已做 RoPE 的 Kᴿ；Indexer 另有自己的 Kᴵ 缓存（量化实现还需要 scale）。这一次没选中的位置，下一个 query 仍可能选到。

位置 2 被选中后仍保留原来的位置编码；不会因为排到候选列表第 0 行，就改成“位置 0 的 RoPE”。

省下的计算在哪里？

对一个 query，Indexer 仍要给全部 L 个候选做较轻量的评分；更重的主 MLA 只算 k 个位置。整段 prefill 的 Indexer 仍包含二次规模的评分，不能把整个 DSA 都说成 O(Tk)。

DSA 的训练会让 Indexer 学会挑选重要位置。Top-k 的分数和主注意力权重是两套东西；稀疏输出通常也不等于全量 MLA 输出。
