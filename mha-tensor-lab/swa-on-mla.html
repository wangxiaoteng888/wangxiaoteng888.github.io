相对 DSA，具体换了什么？

DSA：qr / input → Indexer Q、K、头权重 → index_scores → Top-k 编号。这里换成：query 位置 t + 窗口 W → 起止位置 → window_indices。同一行的所有主头共享这组位置；请求之间互不访问。

window_indices 是整数 token 位置，不是注意力分数，也不是物理 KV Cache block 编号。SWA 是另一种选择规则，不是在 DSA 后面再加一步。

真正的注意力分数仍然由 Q 和 K 算

先按窗口选 K/V，再用原 q_states 与 selected_k 点积，除以 √192，屏蔽无效槽并做 softmax，最后对 selected_v 加权。W=32 时，主权重为 (2,16,128,32)，不是 index_weights。

第二种视图用完整 (2,16,128,128) 分数加窗口 mask 表达同一个规则；它不省已经算过的完整 QK。真正省计算需要内核只处理窗口内的位置。

窗口缓存：保留每个 token 的什么？

沿用 MLA 时，每个保留 token 仍保存归一化的 compressed_kv 512 维 + 已旋转 k_pe 64 维。纯 SWA 解码可用最多 W 个位置的滚动缓冲，不需要 Indexer 的 index_k 缓存。

例如 W=32，处理 t=127 时使用 token 96～127；处理 t=128 时使用 97～128。逻辑位置继续递增，RoPE 仍用原位置，不能把循环槽位当作位置编号。是否能释放底层存储还取决于共享与运行时管理。

为什么图中还是 128 个 token？

这是无旧前缀的一次性 prefill：要为全部 128 个 query 计算输出，所以投影结果有 T=128。缓存只保留窗口是逐步解码的保留策略，不意味着 prefill 一开始就丢掉前面 token。

selected_k / selected_v 的五维形状是按 query 选取的逻辑表示，内核可以直接按窗口访问，而不物化复制张量。前几行不足 W 个候选，用 −1 示意无效槽；必须屏蔽它，不能直接把 −1 当数组索引。
