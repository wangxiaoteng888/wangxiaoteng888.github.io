“压缩”这次压的是 token 轴

旧 MLA 的压缩主要让每个 token 的 KV 表示更小。这里 CSA 的压缩器把条目数量从 128 → 32，每条仍为 512 维。它是学习到的逐特征加权池化，不是直接 reshape，也不是简单平均。

压缩率 r=4；实现里每 4 个 token 输出一条，并与前一组 4 个 token 的信息重叠融合。首条只有当前组有效。因此条目 Cⱼ 的来源通常覆盖两组，不能只把 Cⱼ 理解成一个原始 token。

Top-k 选中的编号是什么？

它是 0～31 的压缩条目编号，不是 0～127 的原 token 编号，更不是 vLLM 物理 block 编号。SWA 索引仍是原 token 位置。主压缩 cache 与 Indexer 压缩 cache 按同一个条目编号对齐，但特征维度和投影不同。

本页按公开参考代码的完成边界：j < floor((t+1)/4)。例如 t=2 尚无完成条目；t=3 可以读取 C₀。每行都屏蔽未来和不足 Top-k 的槽。论文使用更抽象的块位置记法，这里以链接的实现为准。

真正缓存哪些内容？

主注意力：近期窗口的 512 维共享 KV，以及历史压缩条目的 512 维共享 KV。Indexer：历史压缩条目的 128 维 Index Key。另有压缩器尚未完成的尾部状态、重叠状态，以及实现相关的量化信息。

SWA 部分可滚动替换；历史压缩条目继续积累，供未来 query 重新选择。不能因当前未入选 Top-k，就删除历史压缩条目。预填充图展示整段临时张量，不等同于最终常驻缓存大小。

一个主注意力，而不是两次独立 softmax

逻辑上先把窗口 KV 和入选压缩 KV 拼接成候选集，主 Q 只对这些候选评分，再统一归一化、加权同一候选集的 V。V4 有每头一个可学习 sink logit，它参与分母但不贡献 V。

内核可以分开处理两路并正确合并归一化统计量，无需真正复制出图里的大候选张量。图中先 gather 再 concat 是语义展开；官方代码拼接两路索引，交给一次 sparse_attn。
